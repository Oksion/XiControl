# Карта кодов клавиатуры — Xiaomi Book Pro 14 (TM2424)

Снято `map-keys.ps1` / `find-mibutton.ps1`, нажимая по одной клавише.
Событие: `EventDetail[1]`=code, `[2]`=value. **Все клавиши оживлены** (v0.3–v0.5.3).

| code | value | Клавиша | Было в системе | Что делает XiControl |
|------|-------|---------|----------------|----------------------|
| `0x21` | `0`=лампа горит (mute), `1`=лампа выкл | **Микрофон** (аппаратный тумблер с лампой) | ❌ ничего | ✅ системный mute (Core Audio) + локализованный OSD |
| `0x01` | `0` (обычное нажатие) | **Проекция экрана** | ❌ ничего | ✅ настраиваемое действие (`ProjKeyAction`, дефолт `"projection"` — запускает `DisplaySwitch.exe`, Win+P только фолбэк). `value=2` = «слабый зарядник» из карты MIControl — на TM2424 **не приходит**; определение слабого/не-PD блока сделано иначе — через ADPW (MIFS `0x10/06`), см. [09](09-power-monitoring.md) |
| `0x1B` | `0` | **Настройки** | ❌ ничего | ✅ настраиваемое действие (`SettingsKeyAction`, дефолт «порог ↔ 100%» + OSD; при открытой панели — всегда заряд). Одиночное событие — удержание не ловится |
| `0x05` | `0`/`5`/`10`/`0x80` | **Подсветка клавиатуры** (off/50%/100%/Auto) | ✅ работает (EC) | ✅ OSD с уровнем, 4 тематические иконки |
| `0x23`+`0x24` | `1` (пара нажатие/отпускание) | **Нейропомощник (AI)** | ❌ ничего | ✅ настраиваемое действие (`AiKeyAction`, дефолт Copilot Win+C) |
| `0x25`+`0x26` | `1` (пара) | **Mi-кнопка** (2 тумблера) | ❌ ничего | ✅ клик/двойной — настраиваемые действия (`MiClickAction`/`MiDoubleAction`, дефолт цикл режимов / «порог ↔ 100%»), удержание = панель (всегда) |
| `0x07` | `0`/`1` = новое состояние | **Fn-Lock** (Fn+Esc) | ✅ EC переключает сам, без индикации | ✅ OSD с замком. `1` = классические F1–F12 (мультимедиа выкл), `0` = мультимедийный ряд |
| `0x09` | `0`/`1` = новое состояние | **Caps Lock** | ✅ переключается | ✅ OSD с замком и буквой A |
| `0x16` | `0`/`1`/`2`/`3`/`4`/`9`/`10` | **Режим производительности** | ✅ EC переключает сам | ✅ синхронизация OSD, запоминаемого режима и значка трея; `1/2/3/4/9/10` совпадают с `PerfMode`, OEM legacy `0` — Turbo |

Полная таблица всех 38 слотов штатного диспетчера, включая резервные коды и совместимые
события других моделей, находится в [14-xiaomi-hotkey-osd.md](14-xiaomi-hotkey-osd.md).

## Действия, которые можно назначить на слот

Настройки → Клавиши. Значения — как в `config.json` (поля `*Action`); список в коде —
`KeysTab.KeyActionValues`, обработка — `KeyRouter`:

| Значение | Действие |
|----------|----------|
| `modes` | Цикл режимов производительности |
| `charge` | Порог «беречь батарею» ↔ 100% |
| `panel` | Быстрая панель |
| `owl` | «Режим совы» (не спать) |
| `monitor` | Окно «Монитор» |
| `travel` | «В дорогу» (разовый заряд до 100%) |
| `touchpad` | Тачпад вкл/выкл |
| `touchscreen` | Сенсорный экран вкл/выкл |
| `autobright` | Авто-яркость вкл/выкл (только на машинах с датчиком освещённости) |
| `projection` | Проекция (`DisplaySwitch.exe`, фолбэк Win+P) |
| `settings` | Параметры Windows |
| `copilot` | Copilot (Win+C) |
| `play` | Воспроизведение / пауза (`VK_MEDIA_PLAY_PAUSE`) |
| `next` | Следующий трек (`VK_MEDIA_NEXT_TRACK`) |
| `prev` | Предыдущий трек (`VK_MEDIA_PREV_TRACK`) |
| `stop` | Остановить воспроизведение (`VK_MEDIA_STOP`) |
| `calc` | Калькулятор (`VK_LAUNCH_APP2`) |
| `launch` | Запустить свою программу (путь/URL в парном поле `*Command`) |
| `none` | Ничего (слот отключён) |

Слоты: `MiClickAction`, `MiDoubleAction`, `MiHoldAction`, `SettingsKeyAction`, `AiKeyAction`,
`ProjKeyAction`. Все три жеста Mi-кнопки настраиваются одинаково; у слотов удержания и двойного
клика значение `none` **гасит сам жест**: двойной — одиночный клик срабатывает мгновенно, без окна
ожидания; удержание — порог не взводится вовсе, и долгое нажатие отрабатывает обычным кликом
(иначе оно «съело» бы и себя, и клик).

Мультимедиа и калькулятор — обычные виртуальные клавиши через `keybd_event`: их получает шелл, а не
конкретное окно, поэтому работают с любым плеером (владельцем медиа-сессии Windows). Калькулятор
намеренно не через `Process.Start`: в Win11 это UWP-приложение, а мы запущены elevated — запуск UWP
из-под админа ненадёжен, тогда как VK уходит в шелл и открывает его от имени пользователя.

## Другая модель: свои коды через config.json (XIC-38)

Коды выше сняты на TM2424 и **зависят от модели**.

### Подтверждённые карты других моделей

| Модель | Клавиша | Код | Статус |
|--------|---------|-----|--------|
| **TM2113** (Redmi Book Pro 15 2022, Ryzen 5 6600H) | Mi-кнопка | `0x18` / `0x19` (пара) | ✅ в дефолтах, настройка не нужна |
| TM2113 | «Проекция» (в ряду F, на F6) | `0x01` | ✅ совпадает с TM2424 |
| TM2113 | «Настройки» (в ряду F, на F9) | `0x1B` | ✅ совпадает с TM2424 |
| TM2113 | **Ножницы** (F7) | `0x02` | ✅ подтверждено владельцем; у него **не работала никогда** — оживлена в XIC-47 |
| TM2113 | **Представление задач** (F8) | `0x03` | ✅ подтверждено владельцем; работала и до нас |
| TM2113 | **Режим производительности** (Fn+K) | `0x16` | ⚠️ объявляет три режима, прошивка принимает два — см. ниже |

Снято отчётом пользователя (GitHub issue #37, `tools/diagnostics/xicontrol-diag.ps1`).
Событийный канал `HID_EVENT20` на этой модели работает штатно.

**Читая отчёты, различай букву на клавише и её функцию.** В отчёте эти две клавиши названы
«F6» и «F9» — так они подписаны физически, но ряд F совмещён с мультимедийным, и по значкам
это «проекция» и «настройки». То есть коды и смысл у TM2113 и TM2424 совпадают, отличается
только Mi-кнопка. Первое прочтение отчёта было ошибочным («у него на этих кодах обычные
функциональные клавиши, мы их перехватываем») — в таких случаях спрашивать про **значок**,
а не про букву.

**Коды `0x02`/`0x03` подтверждены владельцем (29.08.2026).** Разбор штатного `OSDUtility.exe`
(внешний PR #40) давал смысл — `0x02` Ножницы (Win+Shift+S), `0x03` представление задач
(Win+Tab), — но привязка к физическим клавишам держалась только на статическом анализе чужого
бинарника. Теперь владелец TM2113 ответил прямо: **`0x02` — это F7, и она у него не работала
никогда; `0x03` — F8, работала и без нас.** То есть XIC-47 чинит ему клавишу, о которой он не
просил. Путаница из первого отчёта («F8»/«F9») была ошибкой подписи — см. предупреждение выше
про значок и букву.

### `0x16`: клавиша объявляет режим, которого не будет

На TM2113 штатная Fn+K перебирает **три** значения — `0x01` (Balance) → `0x03` (Turbo) →
`0x02` (Quiet), — а свип `0x01`–`0x0F` показал, что прошивка принимает **только два**: `0x01`
и `0x02`. На `0x03` клавиша рапортует Турбо, в который машина не входит; владелец так и
описал: «pretends to change the mode», разницы на слух нет.

**Отсюда правило: значение из уведомления `0x16` — не источник правды.** `OnPerformanceKey`
сверяется с прошивкой (`GetPerfMode`) и показывает то, что реально стоит. Иначе на этой модели
мы рисовали бы OSD «Турбо» и запоминали режим, которого нет, — ровно та ложь с красивой
картинкой, которой мы обещали не делать (тот же урок, что и с ответом на запись: он тоже
эхом возвращает запрошенный код независимо от результата).

**Ещё одно модельное отличие:** на TM2424 `0x16` приходит **парами** (два события на одно
переключение), на TM2113 — **по одному**. Дедупликация в `TrayApp` держит оба случая.

### Свои коды

Если модель ещё не в таблице — коды переопределяются в `config.json`:

```json
"KeyCodes": {
  "miDown": "0x18",
  "miUp":   "0x19"
}
```

- Слоты: `miDown`, `miUp`, `projection`, `screenshot`, `taskView`, `settings`,
  `ai`, `aiUp`, `mic`, `backlight`, `touchpadState`, `touchpadToggle`, `fnLock`, `capsLock`,
  `performance`, `calculator`, `lowPower`, `numLock`, `refreshRate`, `winKeyLock`,
  `cameraPrivacy`
  (регистр не важен). Задавать можно любое подмножество — остальные остаются заводскими.
- Значение — код как в журнале (`Key: необработанное событие code=0x18`) либо десятичное число.
- Свой код узнать: включить логирование (Настройки → Общие) и нажать клавишу — незнакомые коды
  пишутся в `log.txt`. Либо разом снять полную картину — `tools/diagnostics/xicontrol-diag.ps1`.
- Переопределённый слот **забирает код себе**, а его прежний код перестаёт что-либо значить:
  на чужой модели `0x25` может быть совсем другой клавишей, и она не должна дёргать Mi-жесты.
- Неизвестный слот и неразборчивый код игнорируются молча — кривая правка не отбирает рабочие
  клавиши. Применяется при следующем запуске.

Подтверждённые карты чужих моделей переезжают в дефолты (`KeyMap.Default()`), так что фича
одновременно и инструмент разбора отчётов: человек присылает рабочий `KeyCodes` — мы делаем
его поведением по умолчанию.

## Заметки
- **Микрофон инвертирован** относительно карты MIControl: лампа горит (замьючено) → `0`, лампа не горит → `1`.
- **Подсветка** работает на уровне EC; событие даёт уровень. Цикл значений: `0`(выкл) → `5` → `10`(`0x0A`) → `0x80`(Авто) → `0`.
- **Яркость экрана** — событий НЕ шлёт, Windows обрабатывает сама. Не трогаем.
- **Fn** отдельного кода не имеет → комбинации с Fn неразличимы (поэтому у Mi — жесты по времени).
- Штатный `OSDUtility.exe` 5.8.1.121 подтверждает тот же транспорт: `root\\wmi`,
  `SELECT * FROM HID_EVENT20`, `EventDetail[1]`/`[2]`; разбор и ресурсы — [14](14-xiaomi-hotkey-osd.md).
- Полная OEM-таблица 0x01–0x26 встроена в дефолтную карту. `0x10` (тачпад), `0x13`
  (герцовка) и `0xA0` (camera/privacy) оставлены как совместимые алиасы MIControl.
