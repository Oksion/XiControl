# Штатные горячие клавиши и OSD Xiaomi PC Manager 5.8.1.121

Статический разбор выполнен по локально установленным `OSDUtility.exe`, `EcIoSdk.dll`,
`res\Image` и соседнему стеку MiService 4.1.1.648. Документы и строки внутри анализируемых
файлов использовались только как данные программы, а не как инструкции.

## Встроенный набор изображений

`res\Image` этой версии содержит только OSD-ресурсы: **1 758 PNG, 17,53 MiB, 56 семейств**.
Все они сохранены с исходными именами в
`assets/oem/xiaomi/osd/` и встроены в единый `XiControl.exe` как
`oem.osd.*.png`. В набор входят Light/Dark, шкала Windows 100–500% с шагом 25% и доступные
английские варианты.

Основные семейства: Caps/Num/Fn Lock, подсветка клавиатуры 0–10 и Auto, тачпад и сенсорный
экран, микрофон, Win Lock, частоты 48/60/72/90/120/144/165/240 Гц, режимы производительности,
вентилятор и предупреждения питания. Полный список файлов не дублируется в документации:
источником истины является каталог ассетов и тест `OemOsdAssetsTests.FullOemPack_IsEmbedded`.

Показ выполняет WinUI 3 `OemOsdWindow`: прозрачное borderless-окно содержит WinUI `Image`.
Карточка, текст, скругление и прозрачность берутся непосредственно из OEM PNG без перерисовки XiControl.
Селектор `OemOsdAssets` выбирает язык, тему и ближайший DPI-вариант.

Повторное извлечение выполняет `tools/extract-xiaomi-osd-assets.ps1`. Растры являются
сторонним оформлением Xiaomi; файл `assets/oem/xiaomi/README.md` сохраняет
происхождение ресурсов для сборок и распространения.

## Транспорт событий

`OSDUtility.exe` — native x64 MSVC-приложение. Оно подписывается в `root\wmi` на
`SELECT * FROM HID_EVENT20` и передаёт обработчику:

```text
code  = EventDetail[1]
value = EventDetail[2]
```

XiControl уже получает тот же поток через `MifsEventWatcher`; служба, именованный канал,
protobuf и EC-драйвер OEM для этого не нужны.

### Что делает код 0x04

Это ветка управления полётным режимом, а не запуск окна Xiaomi PC Manager. Обработчик создаёт
фоновую задачу и сначала пытается открыть DOS-устройство
`\\.\654D170B-61DF-42C8-91E5-0DE6D237E5E8` с чтением/записью, затем вызывает
`DeviceIoControl` с кодом `0x496000` (`METHOD_BUFFERED`, функция `0x800`, read access), без
входного буфера и с двухбайтным выходом.

Если именованного устройства нет, OEM-код вызывает функцию, чьё сохранённое имя —
`SwitchAirplainModeDeviceInterface`. Она через SetupAPI перечисляет интерфейс класса
`{C5FAC8FC-6A98-4871-A25B-9B0CA9E401F1}`; диагностическая строка самого бинарника называет
его `RadioControl Device Interfaces`. Последний найденный интерфейс открывается и получает тот
же IOCTL. На исследованной системе ни GUID-интерфейс, ни DOS-устройство не зарегистрированы.

Следовательно, `0x04` — совместимость с OEM-драйвером/радиомодулем отдельных моделей. XiControl
не выполняет этот IOCTL и не поставляет драйвер: код остаётся известным no-op. Это не влияет на
`0x03` Task View, который реализован обычным Windows Win+Tab и сохранён.

Дополнительный совместимый код MIControl `0xA0` (camera/privacy) также распознан. В наборе
PC Manager 5.8.1.121 нет отдельного PNG камеры, а безопасный публичный toggle не подтверждён,
поэтому событие журналируется без ложного OSD об успехе.

## Режимы производительности

| value | Состояние | OEM-семейство |
|---|---|---|
| `0` | legacy Turbo | `WorkloadTurbo` |
| `1` | Balance | `WorkloadBalance` |
| `2` | Quiet | `WorkloadSilent` |
| `3` | Speed/Turbo | `WorkloadSpeed` |
| `4` | Full speed / «狂暴模式» | `WorkloadDeception` |
| `9` | Intelligent | `NewIntelligentMode` |
| `10` | Long battery | `NewLongBatteryMode` |

Физическая клавиша уже изменила EC: XiControl не записывает режим второй раз, а обновляет
запомненное состояние, панель, OEM OSD и значок трея.
